# 账号登录与数据隔离

## 怎么使用

ZeroTier 分享入口现在提供注册、登录、退出和修改密码。安装 Node.js 20 或更新版本，不需要 npm install。

- 当前电脑：双击 `E:\ZeroTier One\start.cmd`，使用启动窗口中的地址；当前配置为 `http://<ZeroTier-IP>:3000`。
- 项目入口：双击 `启动ZeroTier分享.cmd` 或 `npm run share`，当前电脑读取本机配置使用3000端口；无配置时默认3180。
- 朋友需要先加入并获准使用同一个 ZeroTier 网络，再访问、注册自己的用户名。用户名2～24位，密码10～128个字符，允许使用一句话；没有默认账号或默认密码。
- 同一账号可以在手机或其他电脑登录读取已保存的记录。服务器电脑、ZeroTier 和 Node.js 进程需要保持运行。
- 右上角可以改密码或退出。改密码会注销其他设备。未勾选自动登录时，会话最多12小时、空闲2小时或服务重启后失效；刷新同一网址会继续使用有效会话。登录或注册时可勾选“下次自动登录（30天）”，在同一浏览器、同一地址恢复登录，支持服务器重启；退出登录或清理Cookie后需要重新登录。
- 当前没有邮箱、短信验证或自助找回密码，请保存好自己的密码，不要复用其他网站密码。

## 三种模式彼此独立

| 模式 | 登录 | 保存位置 |
| --- | --- | --- |
| GitHub Pages / 普通静态网站 | 不需要 | 当前浏览器 localStorage，沿用原键名 |
| `启动心晴.cmd` 本机版3177 | 不需要 | `E:\ZeroTier One\data\desktop\records.json` |
| ZeroTier Node.js 分享版 | 需要 | `E:\ZeroTier One\data\accounts` 中的各账号文件 |

**旧记录不自动归属新账号。** 升级不修改本机日记或旧浏览器存储，不把第一个注册者设为旧日记所有者。

迁移时先在原来的静态网页或本机版导出 JSON 备份，再在分享版登录自己的账号，点击“导入记录”并确认。导入会替换这个账号的当前记录，先导出当前账号备份。心情编号、时间、多条同日记录、照片和日程四象限保持现有v2格式，兼容旧备份。

如果要迁移升级前同一分享地址的浏览器记录，可先在旧服务中导出；升级后原 localStorage 仍保留。可将同一地址暂时改为普通静态模式后，使用“导出原始数据”恢复，勿清理网站数据。账号页面不会自动展示或上传旧浏览器记录，避免共用浏览器混入他人的日记。

## 数据和备份

默认目录在项目之外。本机 `server-location.json` 或环境变量 `TIANQING_SERVER_HOME` 指定服务器根目录，当前为 `E:\ZeroTier One`。账号目录默认位于根目录的 `data/accounts`；兼容的 `TIANQING_ACCOUNTS_DIR` 覆盖必须仍在根目录内。所有数据不能放在 `public/` 下。更换目录前请停止服务，完整复制原账号目录，否则新目录看起来会没有账号。请只运行一个使用该目录的 Node.js 实例。

- `users/<用户名规范化后的SHA-256>.json`：随机用户ID、用户名和带随机盐的scrypt密码哈希；没有明文密码。
- `records/<随机用户ID>.json`：该账号的心情、日程、偏好和压缩图片。
- 每次更新已有记录前保留同名 `.json.bak` 上一版，原子替换写入。
- 定期备份整个账号目录，包含 users 和 records。用户也可导出自己的完整 JSON 备份。
- 每个账号沿用原来的记录大小与图片数量限制。多设备同时编辑会拒绝旧版本覆盖：先导出尚未保存的记录，再刷新、核对后编辑。不会自动合并两份修改。

本项目的账号隔离阻止用户通过网页读取其他账号；**不是端到端加密**。记录文件没有额外加密，服务器主人和能读取其Windows文件的人员仍能查看；服务器主人的文件备份也要妥善保存。

## 安全边界

登录API只在分享模式启用；本机3177的原日记接口没有被开放到分享端口。会话使用随机令牌和 HttpOnly、SameSite=Strict Cookie，令牌不写localStorage。写入检查精确Origin、自定义请求头、CSRF令牌、当前账号ID和记录版本；旧标签页无法误把A的记录写进B。登录限流，密码使用 Node.js 内置scrypt（N=2^17，r=8，p=1，随机16字节盐）。

当前入口是 **HTTP，仅用于可信 ZeroTier 私有网络**；没有配置HTTPS，因此Cookie不能设置Secure。不要将此HTTP端口转发到公网。将来公开托管应单独配置HTTPS和对应的Secure Cookie、可信代理与Origin校验。本次没有修改防火墙规则，也没有引入外部账号服务或运行依赖。

设计参考：[Node.js crypto](https://nodejs.org/api/crypto.html#cryptoscryptpassword-salt-keylen-options-callback)、[OWASP密码存储](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)、[OWASP会话管理](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html)。

`npm test` 覆盖账号隔离、密码验证、登出、重启恢复、超时、限流、跨站保护、旧备份和图片、损坏文件保护、多设备冲突，以及旧静态/本机功能。浏览器验证使用独立测试目录，不读取真实个人记录。

## 个人中心

登录后从侧栏“个人中心”、右上角昵称或天气头像进入。可查看登录用户名、注册日期、全部已保存的心情/记录日/日程/照片数量，并修改昵称、天气头像和一句话简介；用户名保持不变，修改密码和退出也可在这里操作。资料仅当前账号可通过接口访问，不建立公开用户列表。服务器主人仍可管理账号文件。

资料保存在账号文件的 `profile` 字段，独立于日记JSON。老账号缺少该字段时默认使用用户名、晴天头像和空简介，首次保存才补充，不批量重写旧账号或记录。昵称、头像会随登录会话返回，简介只在个人资料接口返回；密码哈希、盐、文件路径不会返回。用户导出的日记备份格式不变，个人资料由服务器账号目录的完整备份保存。

## E盘集中保存

此电脑的服务器根目录为 `E:\ZeroTier One`，本地 `server-location.json` 仅记录目录位置并已加入Git忽略。通用源码没有本机配置时使用项目的 `private/server`，不再自动使用LOCALAPPDATA；配置损坏或目录不可写会报错，不会改存C盘。

- `data/accounts`：账号资料、密码哈希、日记和图片；记录的上一版 `.bak` 仍在同目录。
- `data/desktop`：单人本机版记录，与分享账号隔离。
- `logs`：运行日志，每份约5MB轮换，保留上一份；不记录请求正文、Cookie、密码或日记。
- `temp`：临时文件；`cache`：启动入口使用的Node/npm缓存。
- `backups`：迁移原件及迁移校验清单，包含私人数据，请勿上传。

移动整个服务器目录前先停服、完整备份并同步本地位置配置。服务会比较保存位置标识，禁止错误复用仍在写旧目录的服务；勾选自动登录的有效会话可跨重启恢复；普通会话需重新登录。备份要包含账号目录的users和records，单独复制日记JSON不能恢复账号密码。

## 下次自动登录

登录和注册页可自行勾选“下次自动登录（30天）”，默认不勾选。浏览器保存HttpOnly Cookie，页面不保存密码，也不把登录凭证写进localStorage。服务端仅在勾选时，将会话凭证的SHA-256摘要、账号ID和到期信息保存到 `E:\ZeroTier One\data\accounts\sessions`，会话文件不保存原始登录令牌或明文密码；普通登录只保存在内存中。30天为本次登录起的固定上限。

同一浏览器刷新、重新打开同一网址或服务器重启后，可恢复仍有效的自动登录。换浏览器、无痕模式清理、删除Cookie、主动退出、密码修改或到期都会要求重新登录。退出立即删除该设备凭证；修改密码会提升账号会话版本并使其他设备的普通和自动登录失效。恢复旧账号备份时不要恢复sessions目录，以免复用旧设备的登录状态。

普通刷新不应导致反复登录，服务更新前的旧内存会话需要重新登录一次。当前仍是可信ZeroTier私网HTTP服务；会话规则参考 [OWASP会话管理](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html)。

本机站点管家位于 http://localhost:3190，使用独立管理员账号。管理员可以查看记录、停用/恢复账号、强制退出全部设备、导出与备份。旧账号缺少disabled/authVersion字段时按正常账号/版本0处理，停用和下线会提高版本使旧凭证失效。后台仅绑定127.0.0.1，不修改防火墙。
