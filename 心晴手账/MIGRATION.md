# 手账数据结构 v2

保留浏览器键名 `tianqing.records.v1`，在 JSON 内增加 `schemaVersion: 2`。仍支持没有版本字段或版本为 1 的旧备份。校验函数同时承担幂等归一化：已经迁移的记录再次读取、保存和导入，不会重新生成编号或时间。

## 心情记录

同一天允许多条。每条具有 `id`、`date`、`recordedAt`、`createdAt`、`updatedAt`、`timeUnknown`、`images`。新增会追加；编辑和删除仅按 ID 操作。

旧记录没有编号时，按旧备份中的日期及位置补稳定编号。缺失时间使用该日期的 UTC 零点占位，并设置 `timeUnknown: true`；界面显示“时间未记录”，不会把占位时间展示为真实记录时间。用户可编辑补充真实时间。

首页和周览展示当天最新记录及条数；日历按日期汇总，详情展示全部卡片。打卡天数和连续天数按日期去重；天气分布按记录次数统计，每日强度趋势取当天全部记录的平均值。

## 日程和偏好

新日程用 `important` 和 `urgent` 两个布尔值保存四象限。旧高→重要且紧急，中→重要不紧急，低→不重要不紧急。已有布尔字段优先；保留兼容的旧 `priority` 字段。

分类仍保存为普通字符串，允许自定义名称。`preferences.recentCategories` 保存最多 8 个最近自定义分类；`preferences.breathing` 保存吸、呼秒数（各 2～8 秒）。这些字段会随 JSON 备份保存。

## 图片和空间

每条最多 3 张图片。选择 JPEG、PNG、WebP 后通过浏览器 Canvas 转为 JPEG，长边至多 1280 像素，质量从 0.7 开始，必要时进一步降低质量和尺寸，单张压缩后至多 160KB。原图超过 15MB 或 4000 万像素会被拒绝。

图片以 JPEG data URL 保存在记录中，导出为一份完整 JSON，不依赖临时文件或外部链接。导入时校验张数、格式、大小，并尝试实际解码；不接受 SVG 或远程图片地址。

保存前保守限制序列化后的 UTF-16 大小约 4.5MiB，以及备份 UTF-8 大小 5,000,000 字节。浏览器实际限额可能更低，仍会捕获写入失败；旧记录和未保存的表单不应被清空。导出使用紧凑 JSON，保证本版本正常保存的记录可完整导入。图片较多时仍需减少附件并导出长期备份；当前未改为 IndexedDB。

## 迁移备份

- 浏览器：首次把旧记录保存为 v2 前，在 `tianqing.records.v1.migration-backup` 保留原字符串，不自动覆盖已有迁移备份。如果空间不够则保存失败，请先导出备份。
- 本机版：首次保存旧文件时，保留同目录 `records.json.migration.bak`，不随以后保存轮换；`records.json.bak` 继续保存上一版。
- 已有文件内容异常时继续拒绝静默覆盖。旧数据目录及导出的个人备份不进入 Git。

## 验证范围

`npm test` 包括原有 12 项检查和新增迁移、草稿确认、同日多条、分类/四象限、附件、容量保护、呼吸边界测试。表单流程使用独立 DOM 模型；图片压缩测试使用浏览器 API 模型。这些测试不替代真实浏览器中的触摸、布局、减少动态效果和图片解码验收。
